## 0. 핵심 시나리오 (한 줄 요약)
품절위험 SKU를 AI가 예측 → Dataverse에 발주추천 레코드 생성 → Teams Adaptive Card로 승인 요청 → 클릭 한 번으로 발주 확정. 추가로 2026-08-20을 "오늘"로 고정해 9월 held-out 데이터와 예측을 대조 검증.

## 1. 크로스커팅 계약 (확정 — 여기서부터 각자 병렬 작업 가능)

### 1-1. Dataverse 테이블: `ReorderRecommendation` (핵심 필드만 확정)
| 필드 | 타입 | 설명 |
| --- | --- | --- |
| sku_code | Text (PK) | 대상 SKU |
| predicted_demand | Number | 예측 수요량 |
| recommended_qty | Number | 추천 발주량 |
| risk_score | Number | 품절위험 스코어 |
| status | Choice | Pending / Approved / Rejected |
| created_at | DateTime | 생성 시각 |
| approved_by | Lookup(User) | 승인자 |

→ 세부 필드(반려사유, 예측근거 등)는 **Azure 인프라 롤이 Week 0에 확장 설계**. 레코드 생성 트리거 조건(재고 리오더포인트 도달)은 [[23. Alert & Trigger Rules]] 1번 행 기준.
> **risk_score 산출 공식**(재고소진임박도 × 인기도가중치)은 2026-08-26 [[23. Alert & Trigger Rules]]에서 확정 — ML·모델링 롤 산출물에 포함되며, 예측근거 자연어 설명([[21. Appservice Core model]] 7절)의 근거 데이터로도 재사용.

### 1-2. Security Role: 2종만 확정
- `Reorder Approver` — 승인/반려 가능
- `Viewer` — 읽기 전용
→ 세분화 필요 여부(부서별 추가 롤 등)는 롤 담당자 판단.

### 1-3. 데이터 흐름 순서 (누가 누구에게 뭘 넘기는지)
`Data Factory 배치` → `ML 예측(로컬 학습, 결과를 직접 Dataverse에 적재)` → `Dataverse ReorderRecommendation 레코드 생성` → `Power Automate 트리거` → `Teams Adaptive Card` → `승인 시 Dataverse 상태 업데이트` → `React 대시보드가 Dataverse 조회`

(별도 서빙 레이어 없이 Dataverse 단일 저장소 구조. 근거: [[22. Cost Plan]])

### 1-4. 9월 held-out 검증 데이터
- 학습 데이터 cutoff: **2026-08-20**
- 검증 대상 기간: **2026-08-21 ~ 09-20**
- held-out 데이터는 `generate_v4.py` 확장으로 생성하되 모델 입력에서 제외 (데이터 파이프라인 롤 담당)
