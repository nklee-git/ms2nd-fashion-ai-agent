## 🎯 배경
기존 가상데이터는 프로모션 배수, 카테고리 가격 등을 전부 설계자가 가정한 값으로만 채웠습니다. 여기에 **날씨(24절기)**, **체형(신장 분포)**, **퍼스널컬러** 3가지를 실제 데이터/도메인 지식으로 보강해 시뮬레이션의 설득력을 높입니다.

- ⚠️ 실시간 일별 데이터는 서비스키 인증이 필요해 이번 라운드는 미연동 — **평년값을 월 15일 기준으로 두고 인접 월 사이를 선형보간**해서 일 단위 근사 기온을 만들었습니다 (`get_temp()` 함수)
- 24절기(입춘~대한) 날짜표도 함께 코드에 넣어뒀지만, 실제 수요 가중치 계산은 절기 단위보다 촘촘한 일 단위 보간을 사용합니다

## 🌡️ 카테고리별 기온 민감도 (설계값, 기준 기온은 실측)
| 카테고리 | 민감도 방향 | 계산식 |
| --- | --- | --- |
| OUT(아우터) | 추울수록 수요↑ | `1 + max(0,(18-기온)/18) × 1.5` |
| DRS(원피스) | 따뜻할수록 수요↑ | `1 + max(0,(기온-15)/15) × 1.2` |
| TOP | 완만하게 따뜻할수록↑ | `1 + max(0,(기온-10)/25) × 0.4` |
| PNT | 완만하게 추울수록↑ | `1 + max(0,(15-기온)/25) × 0.5` |
| CLR·ACC | 계절 둔감 | 1.0 (고정) |

**검증 결과**: OUT 카테고리 판매 비중이 여름(6~8월) 23~35% → 겨울(11월, 2월) 53~55%로 뚜렷한 계절성을 보임 (nqnq.db 실측)

## 📏 체형 데이터 — 20대 여성 신장 분포
| 신장 구간 | 비율 | 매핑 사이즈 |
| --- | --- | --- |
| 155cm 미만 | 7% | XS |
| 156~160cm | 29% | S |
| 161~165cm | 37% | M |
| 166~170cm | 23% | L |
| 170cm 이상 | 4% | XL |

- 출처: 2018 디지틀조선일보 2030 여성 신장 분포 설문(37%/29%/23%/7%/4%), 국가기술표준원 사이즈코리아 7차 조사(2015)의 20대 여성 평균키 160.9cm와 정합
- PANTS(5단계: XS/S/M/L/XL)는 위 표 그대로, TOP/CLR/OUT/DRS(3단계: S/M/L)는 XS+S를 S로, L+XL을 L로 합산(S 36%/M 37%/L 27%)
- **검증 결과**: 생성된 PANTS 주문의 실제 사이즈 분포가 S 28.4%/M 36.8%/L 23.5%/XL 4.1%/XS 7.2%로 목표 실측치와 거의 정확히 일치

## 🎨 퍼스널컬러 데이터 — 의도적으로 ML 대상에서 제외
퍼스널컬러(웜/쿨/뮤트)는 사이즈코리아 같은 국가 통계나 과학적 측정 데이터가 존재하지 않습니다. 뷰티 컨설팅 업계의 경험적 분류 체계이지 인구통계 조사 항목이 아니기 때문입니다. 그래서:
- WRM/COOL/MUT 비율은 **균등 가정(각 1/3)**을 그대로 유지
- ML 기반 예측이 아니라 **룰 기반 매핑**(피부톤 언더톤 → 컬러 팔레트)으로 접근하는 것이 정직한 방법이라 판단
- 향후 실제 퍼스널컬러 진단 서비스 데이터(예: 자체 진단 설문 결과)를 축적하게 되면 그때 실데이터 기반으로 전환 검토

## 🔧 왜 "실제 사이트 구축"이 아니라 "공개데이터+ML"을 선택했는가
검토 결과 실제 페이크 쇼핑앱을 만들어 사용자 행동 데이터를 수집하는 방안은 기각했습니다:
- 실사용자 확보(콜드스타트) 자체가 별도 스타트업 과제 수준의 난이도
- 체형/퍼스널컬러 같은 데이터를 실사용자에게서 수집하면 개인정보보호법(PIPA) 적용 대상이 됨
- 프로젝트 범위가 "AI 네이티브 유통관리 툴의 데이터 기반"에서 "실제 커머스 서비스 운영"으로 바뀌어버림

대신 공개된 실제 통계(기상청, 사이즈코리아 계열 조사)로 시뮬레이션을 조건화하는 방식을 택해, 범위를 지키면서도 데이터의 현실성을 높였습니다.
