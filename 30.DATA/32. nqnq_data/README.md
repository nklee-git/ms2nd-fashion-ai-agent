# NQNQ 가상데이터 생성 결과 (v4 — SKU 확장 & 롱테일 반영)

## v3 대비 변경 배경
매출 목표(Y3 1,000억) 대비 SKU가 243개뿐이라 SKU당 평균 연간 판매량이 약 7,600개로
비현실적이었음. 신규 카테고리(신발 등) 추가는 보류하고, **기존 6개 카테고리 안에서
디자인 수를 확장 + 인기도 티어(HERO/STEADY/NICHE) 도입**으로 해결.

## 핵심 변경점
1. **SKU 243 → 530개** (베이직 428 + 트렌드캡슐 102)
2. **디자인 라인업 확장**: TOP 5종/PNT 4종/CLR 2종/OUT 3종/ACC 5종/DRS 2종 (기존 대비 각 2~3배)
3. **인기도 티어**: HERO(3.0x)/STEADY(1.0x)/NICHE(0.3x) 판매 가중치로 롱테일 구조 구현
4. **동적 재고정책에 티어 반영**: 재주문점·파레벨·초도물량 전부 `tier_ratio_for()`로 카테고리 평균 대비 상대 비율 적용
5. **미달 시나리오 로직 개선**: 재고 버퍼(특히 HERO)가 너무 커서 공급망 이슈가 흡수되던 문제 발견 →
   재고 기반 지연 대신 **일별 주문 타겟을 직접 스케일링**하는 방식으로 전환 (더 확실하고 예측 가능)

## 파일 구성
- `models.py` — SQLAlchemy 스키마 (popularity_tier 필드 포함)
- `generate_v4.py` — 베이스 시나리오 생성 스크립트
- `generate_v4_miss.py` — 미달 시나리오 생성 스크립트 (일별 타겟 직접 축소 방식)
- `add_wholesale.py` — 홀세일 파일럿 데이터 추가 스크립트
- `nqnq.db` / `nqnq_scenario_miss.db` — 생성된 SQLite DB (각 약 490~500MB)
- `csv_preview/` — 주요 테이블 CSV 미리보기 (popularity_tier_performance.csv 신규 추가)

## 분기별 목표 대비 실제 (베이스 시나리오, 대부분 98~118%)
전체적으로 v3와 유사한 정확도를 유지하되, 롱테일 구조 도입 이후 일부 분기(Q8, Q9)에서
105~118%로 다소 과달성 — 인기 디자인 집중 구매로 인한 AOV 상승 효과로 해석 가능 (억지 조정 없이 유지).

## 단순화 가정
1. 프로모션은 주문량 스파이크로만 반영, SKU 개별 할인가 미반영
2. 취소(주문 status=취소) 미반영
3. 신발(SHOES) 카테고리는 이번 라운드에서 제외 (사용자 결정)
4. Y3 FW 캡슐(2026.09 예정)은 TODAY 이후라 이번 라운드 제외
5. STAFF/TASK/SITE_VISIT/CART_EVENT 등 운영·퍼널 데이터는 백로그 유지

## 재실행 방법
```bash
pip install sqlalchemy numpy --break-system-packages
python3 generate_v4.py        # 베이스 시나리오
python3 generate_v4_miss.py   # 미달 시나리오
python3 add_wholesale.py      # 홀세일 파일럿 추가
```
`DESIGNS_BY_CATEGORY`, `TIER_WEIGHT`에 디자인/티어를 추가/조정하면 전체 데이터가 다시 계산됩니다.
