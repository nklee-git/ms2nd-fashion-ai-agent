## 🎭 컨셉

2차 프로젝트 최종 발표 자체를 **롤플레이 세일즈 피치**로 구성한다.
- **발표팀 = Microsoft 판매사원.** Microsoft 제품(Dynamics 365 + Power Platform)을 파는 입장에서 발표를 준비해온 컨셉.
- **청중 = 카카오스타일 임원진** (실제로는 심사위원/강사). 이 제품을 도입할지 말지 **구매 결정권자**로서 발표를 듣는다.
- **배경 시나리오(가상)**: 지그재그가 무신사 스탠다드를 겨냥해 자사 PB 브랜드 **NQNQ**를 준비 중. 이 상황에서 기존 ERP(SAP)를 어떻게 보완/대체할지가 화두.

## 🗺️ 발표 구조 (7단계)

1. **상황 설정 (Hook)** — 지그재그가 무신사 스탠다드를 겨냥해 PB 브랜드 NQNQ를 준비 중이라는 가상 시나리오 제시
2. **고객 진단 (Pain Point)** — 현재 SAP ERP 분석: 범용 ERP라 패션 버티컬 특화 기능(체형·날씨 기반 수요예측) 부재, 커스터마이징 비용/속도 문제
3. **솔루션 소개** — NQNQ = Dynamics 365/Dataverse 위에 얹는 **모듈형 애드온**. "뗐다 붙였다" 가능해 기존 SAP를 뜯어내지 않고 병행 검증 가능하다는 점이 도입 리스크를 낮추는 핵심 세일즈 포인트
4. **라이브 데모 (발표의 클라이맥스)** — 품절위험 SKU 예측 → Teams Adaptive Card로 승인 요청 → 클릭 한 번으로 발주 확정. **이 한 장면이 전체 발표의 핵심이며, 나머지 슬라이드는 이 장면의 설득력을 뒷받침하는 배경**
5. **차별화 포인트** — 패션 버티컬 AI(108만 건 실측 검증 데이터) + M365 생태계 통합(Teams/Excel/Power BI) + Dataverse 기반이라 기존 D365 데이터 손상 없이 결합
6. **비용/ROI** — SAP 애드온 개발 대비 비용, 데이터로 뽑은 구체적 수치(분기별 목표 정확도 99~100%, 반품율 등)로 도입 효과 정량화
7. **클로징** — 파일럿 도입 제안 + AppSource 등재 로드맵으로 "이미 검증된 확장 경로가 있다"는 신뢰로 마무리

## 🔮 예측 검증 시나리오 — "커머스 전 과정을 예측한다"는 증거

라이브 데모(4번, 발주 승인 클릭)가 "AI 예측이 실제 액션으로 이어진다"를 보여준다면, 이 시나리오는 **"그 예측 자체가 믿을 만하다"**를 보여준다. 둘이 합쳐져야 설득력이 완성됨.

### 설계 원리
- nqnq.db의 시뮬레이션 시계는 **2026-08(현재 Y3 SS 완료, FW 시작 전)**에 멈춰 있음 → 9월 데이터가 아직 없다는 게 오히려 기회
- **2026-08-20을 "오늘"로 고정** → 모델은 2024-03-01~2026-08-20 데이터로만 학습
- 9월 한 달(~2026-09-20)의 "실제" 데이터는 기존 생성 스크립트(`generate_v4.py`류, Y3 FW 시즌·트렌드캡슐·프로모션 캘린더 규칙 그대로 적용)로 **미리 만들어두되 모델에는 숨기는 held-out 정답지**로 준비
- 발표에서: 예측 공개 → 액션 제안 → (짜잔) 실제 9월 데이터 공개 → 오차율 계산, 순서로 진행

### 커머스 프로세스 단계별 예측 항목

| 단계 | 예측(모델 아웃풋) | 추천 액션 | 실제와 대조 |
| --- | --- | --- | --- |
| 기획/발주 | SKU별 9월 수요량 (가을 아우터 신규 캡슐 포함) | 품절위험 TOP N 자동발주 추천 (→ 4번 라이브 데모와 연결) | 실제 9월 판매량/품절 여부 대비 오차율 |
| 마케팅 | 프로모션 반응 예측(가을 신상 캡슐) | 채널별 예산 배분 방향 제안 (Teams 협의, 콘텐츠 생성 아님) | 실제 캠페인 성과 대비 오차율 |
| 판매 | 일별·카테고리별 매출 예측 | - | 실제 매출 대비 오차율 (기존 분기별 정확도 99~100% 실적처럼 %로 제시) |
| 재고/반품 | 반품율 예측(신상품 초반 반품 高 패턴) | 재고 버퍼 조정 제안 | 실제 반품율·재고회전율 대비 오차율 |
| 피드백 | 예측-실측 오차 자동 분석 | 다음 사이클 재학습 트리거 제안 | (루프를 닫는 마무리 — "이 오차만큼 다음 달엔 더 정확해집니다") |

### 발표에서의 효과
- 카카오스타일 임원진(청중) 입장에서 가장 궁금한 건 "예측을 믿을 수 있는가"인데, 이 시나리오가 바로 그 증거를 눈앞에서 만들어 보여줌
- 기존에 이미 확보한 "분기별 목표 정확도 99~100%" 수치와 자연스럽게 이어져 — 과거 3개년치 검증에 더해 "미래 한 달"도 라이브로 검증하는 구조가 됨

## ✅ 이 구조가 기능 우선순위를 결정하는 방식

3주 스프린트에서 실제로 만들어야 할 건 **4번(라이브 데모)이 실제로 동작하는 것 하나**로 수렴한다.
- 데이터 파이프라인·ML·Azure 인프라·RAG 롤은 전부 이 데모를 뒷받침하는 백엔드
- 대시보드·프론트는 이 승인 흐름의 "현황판"(이력·대기 건) 역할로 축소
- 부서별 KPI 대시보드처럼 화면을 여러 개 쪼개는 시도는 지양 — 하나의 흐름을 확실하게 보여주는 데 집중
